## 5. Design decisions (instruction §9.1)

- **PD-1, the prototype is proposal §6.3's design, improved within R-1 to R-6.** Kept: the clone flags and the alternates refusal (R-1); per-entry metadata (R-2, R-3); `state_changes` with a 20-line cap and a count; the print loop in `main`; three test functions in the positions §6.3 chose. Improved:
  - metadata entries are tuples of typed fields rather than formatted strings, so `state_changes` compares fields directly and parses nothing (PD-3);
  - every kind of entry names the fields that moved (tracked, ignored, directory and git metadata), where §6.3 named fields only for git metadata. R-2 asks for "each differing entry with the fields that moved" (PD-4);
  - the HEAD and status lines carry no commit ID and no `git status` output, where §6.3 printed both commit IDs. R-2 allows "paths and field names only" (PD-4);
  - the tests set the timestamps of the files they examine to a fixed past instant, so a freshen or rewrite moves `mtime` on any clock, and they assert exactly which entries are named (PD-6);
  - R-5's two README lines, which §6.3 did not include (PD-7).
- **PD-2, R-1 in `make_copy`.** The clone becomes `["git", "clone", "--quiet", "--no-hardlinks", "--dissociate", "--no-checkout", "--", str(repo), str(destination)]`, split over two lines. Right after a successful clone, an existing `<copy>/.git/objects/info/alternates` raises `ToolingError("the throwaway copy still borrows objects from another repository")`. The commit check, the detached checkout and the HEAD check are unchanged. The docstring states why the copy owns its objects (freshen through `--shared`, ctime through hardlinks, `--dissociate` for a borrowing source) and cites QA110-F01. All four copying reports already call `make_copy` (lines 838, 886, 1004, 1525), so none changes.
- **PD-3, R-2 and R-3: the metadata representation.**
  - `_metadata_digest(directory) -> str` becomes `_metadata_entries(directory) -> tuple[tuple[str, int, int, int, int, str], ...]`. The walk and its order (`sorted(directory.rglob("*"))`) are unchanged.
  - A file or symlink gives `(rel, st_mode, st_size, st_mtime_ns, st_ctime_ns, sha256)`. The SHA-256 is of the file's bytes, or of a symlink's target, outside `objects/`, and `""` inside it, so an object is still not read.
  - A directory gives `(f"{rel}/", -1, -1, -1, -1, "")`: its name only, as before.
  - `RepositoryState.metadata` becomes `tuple[tuple[str, tuple[<entry>, ...]], ...]`, one item per git directory, sorted as before.
  - **R-3 holds by construction.** The old digest fed, per file, the path, mode, size, mtime and ctime and, outside `objects/`, the bytes or link target; per directory, the name. Each new entry holds the same fields, with a SHA-256 of the same bytes. `main` still compares whole states by equality. The existing `test_repository_state_covers_ignored_files`, which pins the guard's precision cases (an empty metadata directory, an overwrite of an unreachable object, a `config` rewrite with its own bytes), passes unchanged.
  - Three constants name the fields after the path for the violation lines: `_FILE_FIELDS = ("mode", "size", "mtime", "ctime")` for tracked and ignored entries, `_DIRECTORY_FIELDS = ("mode", "mtime", "ctime")` and `_METADATA_FIELDS = ("mode", "size", "mtime", "ctime", "sha256")`. They mirror the tuple layouts of `_lstat_entries`, `_directory_entries` and `_metadata_entries`.
- **PD-4, R-2: `state_changes(before, after, limit=20) -> list[str]`.**
  - Order: `HEAD`, `git status`, then tracked, ignored and directory entries, then git metadata by directory; each group sorted by path.
  - Line forms: `HEAD`; `git status`; `<kind> <path> (<fields>)` with kind `tracked`, `ignored`, `directory` or `git metadata`, where a git-metadata path is `<absolute git directory>/<relative path>`. `<fields>` lists the fields that moved, comma-separated, or is `created` or `removed`.
  - A helper `_entry_changes(kind, before, after, fields, prefix="")` builds one group.
  - Cap: more than `limit` lines become the first `limit` lines and `and <n> more`.
  - Nothing else is printed: the field named `sha256` appears, never a digest value, and no commit ID, file content or environment value. Example, from V-3: `PREPUSH_CHECK_READ_ONLY_VIOLATION: changed: git metadata <clone>/.git/objects/pack/pack-d5d88524f3a45f030d6bdebc189ef5aeaece729e.pack (mtime, ctime)`.
- **PD-5, `main`.** After the existing violation line (1743–1744), `for line in state_changes(before, after): print(f"PREPUSH_CHECK_READ_ONLY_VIOLATION: changed: {line}", file=sys.stderr)`, then `return EXIT_READ_ONLY_VIOLATION`. Stdout, the exit codes and the result line are unchanged.
  - The refusal path at line 1719 keeps its output. It prints a refusal line, not the violation line, and it can return 4 only when the temporary directory `mkdtemp` created resolves inside the repository after the directory chosen for it was checked to be outside. No real input produces that (addendum 2.11 rule 5), so it gets no named lines.
- **PD-6, R-4: four test items,** inserted after `test_repository_state_covers_ignored_files`, before the "every report on the repository" section. The existing 137 tests are unchanged: the test file's diff only adds lines (+87/−0).
  - Helpers: `PAST_NS` (a fixed past instant, 2020-09-13T12:26:40Z in nanoseconds); `_set_past(paths)`, which sets each path's atime and mtime to it; `_write_existing_blob(repo)`, which runs `git hash-object -w --stdin` of `alpha\n` in `repo`.
  - **(a)** `test_a_copy_owns_its_objects_so_a_write_in_it_cannot_freshen_the_source[packed]` and `[loose]`. A synthetic source, packed (`repack -a -d`, `prune-packed`) or loose. The file that holds `a.txt`'s blob (the one pack, or the loose object) is identified, and every object file is set to the past. A `make_copy` copy has no alternates, the source state is equal after the copy and after a write of the existing blob in it, and `state_changes` is empty. The negative control in the same test: a `--shared` copy with a detached checkout leaves the source equal; the same write makes the source differ in `metadata` only (head, status, tracked, ignored and directories equal), and `state_changes` is exactly `["git metadata <git dir>/<held object file> (mtime, ctime)"]`.
  - **(b)** `test_a_copy_of_a_source_that_borrows_objects_borrows_none_itself`. A packed base and a `--shared` clone of it as the source; the source's alternates file is asserted to exist, and the base's object files are set to the past.
