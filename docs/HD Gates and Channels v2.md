## **Purpose**

Explain why some **gates connect to more than one channel**, what that means in lived experience, and how to handle it safely in computation. Provide a **full channel list (36)** and a **gate glossary (64)** with concise meanings, then ship a **JSON appendix** your team can use immediately.

---

## **Plain‑English overview**

Most gates are like a street that ends in a single bridge: they connect to **one** opposite gate to make **one** channel. A few gates are **junctions** – they can connect to **more than one** opposite gate, forming different channels depending on what they meet. This is by design, not a mistake.

The classic case is the **Integration network**: gates **10 (G)**, **20 (Throat)**, **34 (Sacral)**, and **57 (Spleen)**. These four share endpoints and can combine in multiple legitimate ways. That’s why you’ll see, for example, **Gate 20** in more than one channel (20‑34, 20‑57, 10‑20). Each completed channel has its **own feel** because the *other* center changes the expression of that shared gate.

Think of a junction gate as the same musician sitting in with different bands. Same instrument, different sound depending on who else is playing.

---

## **Which gates do this (junction gates)**

Only the **Integration** set does this in the canon: **10, 20, 34, 57**. They form **six** channels among them (the complete graph on these four gates):

* **10‑20 (Awakening)** — G ⇄ Throat  
* **20‑34 (Charisma)** — Throat ⇄ Sacral  
* **20‑57 (Brainwave)** — Throat ⇄ Spleen  
* **10‑34 (Exploration)** — G ⇄ Sacral  
* **10‑57 (Perfected Form)** — G ⇄ Spleen  
* **34‑57 (Power)** — Sacral ⇄ Spleen

*Note:* **34‑57 (Power)** **is part of the Integration grouping**. Earlier drafts treating it as “outside” are corrected here.

## **What it *means* in real life**

* **Same gate, different partner → different flavor.** 20 with 34 feels like *doing while speaking*; 20 with 57 feels like *intuition speaking now*; 10 with 34 feels like *behavior energized for movement*.  
* **Not redundancy.** Shared endpoints are **intentional overlaps**. Keep each channel distinct in language and logic.  
* **Timing first.** These in‑the‑now geometries are immediate when correct; forcing them with the mind creates pressure.

---

## **Computing implications (do this, not that)**

1. **Model a multi‑edge graph.** Centers are nodes; **channels are edges**; **gates are endpoints** on edges. A junction gate can appear on multiple edges.  
2. **Count per channel, not per gate pair.** For EMs/Compromises, evaluate **each channel separately**. 20‑57 EM ≠ 20‑34 EM.  
3. **Directionality lives at channel granularity.** Compromise \= one partner holds the **full channel**, the other only **one gate** *of that channel*. Record **who compromises whom** and **which gate**.  
4. **Bridge coverage is per split and per channel.** A junction gate may bridge different center pairs (e.g., 10 can bridge G→Throat *or* G→Sacral). Record **center\_path** and **symmetry**.  
5. **Circuit flavor is tied to the channel.** Even when a gate repeats, copy/prompt tone should follow the **channel’s** flavor (e.g., Integration vs Tribal vs Collective).  
6. **UI covenant:** Never expose gates/channels. Translate to **Warm/Open/Cool** \+ humane prompts.

## **Disjoint classification (mechanics; prevents double count)**

Evaluate per channel `c` with A’s endpoints `(a_i, a_j)` and B’s `(b_i, b_j)` as booleans indicating gate ownership:

* **Companionship(c):** `(a_i & a_j & b_i & b_j) == 1`  
* **Compromise(A→B)(c):** `(a_i & a_j) == 1` and `(b_i ^ b_j) == 1`  
* **Compromise(B→A)(c):** `(b_i & b_j) == 1` and `(a_i ^ a_j) == 1`  
* **Electromagnetic(c):** `(a_i ^ a_j) == 1` and `(b_i ^ b_j) == 1` and `(a_i != b_i)`  
* **Null(c):** otherwise

These four are pairwise disjoint and exhaustive. **EM is a single undirected event per channel** (do not count “both directions”). With junction gates, EM may occur on **multiple channels** simultaneously (e.g., 20‑34 and 20‑57); that is correct.

# **1\) Toggle resolver (stdlib-only)**

\# core/config/toggles\_resolver.py  
from \_\_future\_\_ import annotations  
from typing import Any, Dict, Tuple  
from pathlib import Path  
import json, hashlib

\# \---- helpers \----

def \_stable\_bytes(data: Any) \-\> bytes:  
    \# Use your canon; fallback to json with sorted keys if needed.  
    try:  
        from core.stable.sercanon import stable\_dumps  
        return stable\_dumps(data)  \# returns bytes per your canon  
    except Exception:  
        return json.dumps(data, sort\_keys=True, separators=(",", ":")).encode("utf-8")

def \_deep\_set(obj: Dict\[str, Any\], dotted\_key: str, value: Any) \-\> None:  
    parts \= dotted\_key.split(".")  
    cur \= obj  
    for p in parts\[:-1\]:  
        if p not in cur or not isinstance(cur\[p\], dict):  
            cur\[p\] \= {}  
        cur \= cur\[p\]  
    cur\[parts\[-1\]\] \= value

def \_apply\_patch(frozen: Dict\[str, Any\], patch: Dict\[str, Any\]) \-\> Dict\[str, Any\]:  
    \# Apply dotted JSON-pointer-ish keys deterministically (sorted by key)  
    out \= json.loads(json.dumps(frozen))  \# deep copy via stdlib  
    for k in sorted(patch.keys()):  
        \_deep\_set(out, k, patch\[k\])  
    return out

def \_read\_json(path: Path) \-\> Dict\[str, Any\]:  
    return json.loads(path.read\_text(encoding="utf-8"))

def \_sha256\_hexdigest(data\_bytes: bytes) \-\> str:  
    return hashlib.sha256(data\_bytes).hexdigest()

\# \---- main API \----

def resolve\_toggles(  
    frozen\_path: str \= "config/toggles\_v1.json",  
    runtime\_overrides\_path: str \= "config/runtime\_overrides.json",  
) \-\> Tuple\[Dict\[str, Any\], str, bool\]:  
    """  
    Returns: (resolved\_toggles, frozen\_sha, override\_applied)  
    \- frozen\_sha is computed on the \*frozen\* file canonical bytes (not including overrides)  
    \- override\_applied indicates whether a dev/staging patch modified the in-memory toggles  
    """  
    fpath, rpath \= Path(frozen\_path), Path(runtime\_overrides\_path)

    \# 1\) load frozen toggles  
    frozen \= \_read\_json(fpath)

    \# 2\) compute SHA over \*frozen\* config (this is what we ship in meta)  
    frozen\_sha \= \_sha256\_hexdigest(\_stable\_bytes(frozen))

    \# 3\) decide if runtime overrides are allowed (guard is read from \*frozen\* file)  
    allow\_overrides \= bool(  
        frozen.get("experiment", {}).get("allow\_runtime\_overrides", False)  
    )

    \# 4\) apply runtime overrides only if allowed and file exists  
    override\_applied \= False  
    resolved \= frozen  
    if allow\_overrides and rpath.exists():  
        try:  
            overrides \= \_read\_json(rpath)  
            patch \= overrides.get("experiment", {}).get("patch", {})  
            if patch:  
                resolved \= \_apply\_patch(frozen, patch)  
                override\_applied \= True  
        except Exception:  
            \# Be conservative: if overrides are malformed, ignore them and proceed  
            resolved \= frozen  
            override\_applied \= False

    return resolved, frozen\_sha, override\_applied
